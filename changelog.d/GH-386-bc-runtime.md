- Block-compression runtime, M-CONTENT step 1b-iii (GitHub #386): `--textures bc` packs now draw. `render::rhi_format_for` is the one mapping from a cooked texture's format to the RHI format (BC1/BC4/BC5/BC7 and their sRGB variants, ASTC, RGBA16F) for `upload_cooked_texture` and `compose_layer_array`. A compressed format the device cannot sample (`DeviceCaps::texture_bc` / `texture_astc` false) is refused with `Errc::Unsupported` and one error per process that names the fix ("re-cook for this target"), and the texture draws as the error checker; a null handle from the backend is no longer ignored. Shaders rebuild a BC5 normal's z through `unpack_normal` only when the blue channel is exactly 0, so RGBA8 frames and the render goldens are bit-identical (for blue > 0; an RGBA8 texel with blue == 0 gets its z rebuilt too). A BC4 height beside a BC5 normal in a parallax array is widened to BC5 blocks losslessly (`compose_layer_array(..., widen_bc4)` is opt-in, only the parallax array asks for it, and only layers that pass the size/mip checks count). The unsupported-format refusal is logged once; the per-texture upload warnings skip it. Kit3D warns when a BC4 texture sits in a base-colour, ORM, emissive or normal slot. The GL `texture_bc` cap needs S3TC only (BC4/BC5/BC7 are core in GL 4.5) and a driver without an sRGB S3TC extension logs that BC1_SRGB is unsupported; the SDL GPU caps also query the sRGB variants.
