- Block-compression runtime, M-CONTENT step 1b-iii (GitHub #386): `--textures bc` packs now draw. `render::rhi_format_for` is the one mapping from a cooked texture's format to the RHI format (BC1/BC4/BC5/BC7 and their sRGB variants, ASTC, RGBA16F) for `upload_cooked_texture` and `compose_layer_array`. A compressed format the device cannot sample (`DeviceCaps::texture_bc` / `texture_astc` false) is refused with `Errc::Unsupported` and one error per process that names the fix ("re-cook for this target"), and the texture draws as the error checker; a null handle from the backend is no longer ignored. Shaders rebuild a BC5 normal's z through `unpack_normal` only when the blue channel is exactly 0, so RGBA8 frames and the render goldens are bit-identical. A BC4 height beside a BC5 normal in a parallax array is widened to BC5 blocks losslessly. Kit3D warns when a BC4 texture sits in a base-colour, ORM, emissive or normal slot. The GL `texture_bc` cap also requires the sRGB S3TC extension, and the SDL GPU caps also query the sRGB variants.
