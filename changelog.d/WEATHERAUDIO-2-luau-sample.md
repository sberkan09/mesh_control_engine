- Luau rain and wind beds and the weather sample's `WeatherAudio`, M-WEATHERAUDIO step 10c (milestone closed): `weather.rain_level()` and `weather.wind_level()` (read-only, the engine-written `rain_q` and `wind_q` as 0 to 1), `weather.audio_rain_db()`, `weather.audio_wind_db()`, `weather.audio_fade()` and `weather.audio_enabled()` read the first `WeatherAudio` (`mce/kit/weather_audio.h`) and `weather.set_audio{rain_db=, wind_db=, fade=, enabled=}` writes it. Every key is optional and values are clamped to the component's Range (`enabled`: any non-zero number is 1); an unknown key, a non-number (NaN included) or a scene without the component (or a world without weather) raise a named Luau error and write nothing. Typed in `mce.d.luau`. Sample `samples/12_weather`: the Weather entity carries a `WeatherAudio` pointing at two clip-less looping `AudioSource` entities (Rain Bed and Wind Bed, so the sample stays silent) and the script logs `audio:` every 150 ticks (entity count 12 to 14). The scene's state hash changes (600 ticks dc236463f3739995, 2700 ticks 0e772206f8671297, each identical on two runs of the built `mce_player`); `WeatherAudio` leaves `sample_coverage.allow`.
