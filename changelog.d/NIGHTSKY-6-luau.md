- Luau moon and the weather sample's `Moon`, M-NIGHTSKY step 14f (milestone closed): `weather.moon_phase_offset()`, `moon_cycle_days()`, `moon_freeze_phase()`, `moon_inclination()`, `moon_light_intensity()`, `moon_light_color()` (three numbers), `moon_light_shadows()`, `moon_disk_size()`, `moon_disk_intensity()`, `moon_star_density()`, `moon_star_brightness()`, `moon_star_twinkle()` and `moon_enabled()` read the first `Moon` (`mce/kit/moon.h`) and `weather.set_moon{phase_offset=, cycle_days=, freeze_phase=, inclination=, light_intensity=, light_color={r,g,b}, light_shadows=, disk_size=, disk_intensity=, star_density=, star_brightness=, star_twinkle=, enabled=}` writes it (`inclination` is `inclination_deg`, in degrees); `weather.moon_phase()`, `moon_illumination()`, `moon_direction()` (`x, y, z`, the direction the moonlight travels) and `moon_level()` are read-only values from the kit helpers on the current `Environment3D.time_of_day`, the first `WorldClock`'s day (0 without one) and the first `Weather` (the same sources as `mist_level`). Every set key is optional and clamped to the component's Range (`light_color` lanes 0 to 1; `light_shadows` and `enabled`: any non-zero number is 1); an unknown key, a non-number (NaN included), a `light_color` that is not three numbers or a scene without the component (or a world without weather) raise a named Luau error and write nothing, and the setter never adds the component. Typed in `mce.d.luau`. Sample `samples/12_weather`: the Weather entity carries a default `Moon` (entity count stays 14) and the script logs `moon:` every 150 ticks; the clock stays at 5:00, where the day-0 full moon hangs in the west and sinks through the dawn (level 1.000 at tick 0, 0.469 at 450, 0.000 from 1500), so the mist numbers do not move. The scene's state hash changes (600 ticks 3f486cd4e5f37fb2, 2700 ticks 2642cc47d0cf5867, each from the built `mce_player`). User guide 9.19j, 08-3d, 18 and 27.3.
