# M-GROUNDMIST — Morning mist banks and ground fog from the clock and the weather (milestone record)

**Status:** in progress, 13a done (2026-10-22). **Owner: routine 2 thread (the M-VISUAL line).** Follow-up of M-WEATHER, M-WETSURFACE, M-DAYNIGHT (`WorldClock`, `DayCycle`) and the volumetric fog of M-VISUAL 7. Today fog is a single global number: `Weather` adds a kind-dependent `fog_density` to the exp² fog and `DayCycle` keys it by the hour, both uniform in height and distance, so a clear dawn after a rainy night looks like noon with a bit more haze. Real mornings have mist that lies in the low ground, burns off as the sun rises and is thickest when the ground is still wet. No Linear issues (free issue limit); this record is the tracker.

**Goal.** An opt-in kit component `GroundMist` turns the hour of day (`Environment3D.time_of_day`, written by `WorldClock`) and the wetness left by rain (`Weather.wetness`) into a mist level, and `Kit3DExtract` feeds that level into the *existing* volumetric height fog (density, falloff, base height) so the mist hugs the ground and the sun shines through it as light shafts. Where volumetric fog is off (Low tier, or a scene that did not enable it) the same level raises the exp² fog density and pulls its colour toward the mist colour instead. No new shader, pass or render field. A scene without `GroundMist` hashes, simulates and renders exactly as today.

**Not in scope:** a new shader, froxel change or noise-driven patchy fog (the medium stays the existing smooth height fog; patchiness would be a shader job and a follow-up), changing `Weather`, `WetSurfaces`, `DayCycle`, `WorldClock` or `Environment3D` bytes (the last is a wide header; see Design), mist that follows terrain height or a water level (one global base height per component), per-area fog volumes (that belongs with the open-world line), mist sounds, rainbow, stars, moon or aurora (separate ideas, rainbow and aurora need shader work).

## Design

- **Opt-in component, no system, no state.** New component `GroundMist` (`mce/kit/ground_mist.h`, one per scene, the first in ECS order is read, registered by `install_weather`). Pure data, like `CloudLayer`: the level is a pure function of authoring, `time_of_day` and `Weather`, evaluated at extract and in the Luau getter, so nothing is carried between ticks, nothing is hashed beyond the authored fields and save/load needs no care. Authoring (all `Save`, with a `Range`): `strength` 1 (Range 0..2, scales the level), `peak_hour` 6 (0..24, the hour of the thickest mist), `rise_hours` 3 and `burn_hours` 3 (0.1..12, the ramp up before the peak and the burn-off after it; the dawn bump is a smoothstep pair, wrapped over midnight), `base_humidity` 0.25 (0..1, the mist on a dry day), `wet_gain` 0.75 (0..1, how much `Weather.wetness` adds), `weather_damp` (0..1, default 1) scaling the level down with rain, storm and snow weather where mist makes no sense (the kind factor is Clear 1, Overcast 0.8, Rain 0.2, Storm 0, Snow 0.4 times `Weather.intensity`; without `Weather` no damping and `wetness` counts 0), `density` 0.06 (0..1, volumetric extinction per metre at full level), `thickness_m` 6 (0.5..200, the height scale: the extract sets `height_falloff = 1 / thickness_m`), `base_height_m` 0 (-1000..1000, the plane the mist sits on), `exp2_density` 0.02 (0..0.2, exp² fog added at full level when volumetric fog is off), `color` (default 0.78 0.82 0.88, linear, the exp² fallback colour and a mix toward it for the volumetric albedo) and `enabled` 1. No engine-written fields, so there is no padding audit beyond keeping the struct naturally packed.
- **Level function (kit, 13a).** A pure inline `mist_level(const GroundMist&, f32 hour, const Weather*) -> f32` in `ground_mist.h`: `bump(hour) * clamp(base_humidity + wet_gain * wetness, 0, 1) * weather_factor * strength`, clamped 0..1, in f32 with fixed evaluation order (no `pow`/`exp` with platform-dependent results beyond what the extract already uses; smoothstep polynomials only). `hour` outside 0..24, NaN or an inverted range falls back to the defaults; `time_of_day` of -1 (the environment's "off") gives level 0 and the mist stays off, since there is no clock. A zero level returns exactly 0.0f.
- **Extract (13b).** In `Kit3DExtract` right after the fog and volumetrics are built from `env` (`kit3d_extract.cpp` ~834 to ~852) and before `render::apply_quality(quality_, vol)`: if a `GroundMist` exists, `enabled` and the level `L > 0`, then on the local copies only, never on the `Environment3D` resource: when `env.volumetric_fog != 0`, `vol.enabled` stays, `vol.density = min(1, vol.density + L * density)`, `vol.height_falloff = max(vol.height_falloff, 1 / thickness_m)` blended by `L`, `vol.base_height = base_height_m`, `vol.albedo` mixed toward `color` by `L * 0.5`; when it is 0, or `apply_quality` turns the volumetrics off (checked after it), `fog.density += L * exp2_density` and `fog.color` mixed toward `color` by `L`, once, on whichever path the frame really uses (a test checks no double application). `Environment3D` is not edited (it is a wide header; mist needs no field there), the weather's own writes to `fog_density` are untouched and compose additively. With `L == 0` or no component nothing is read or written, so frames are bit-identical.
- **Why no system.** `Weather.wetness` is already an integer-state ramp (`wet_q`) and `time_of_day` an exact rational from `WorldClock`, so their composition is smooth and deterministic by itself. A mist system would only add state to hash and a way to drift. The `Weather` column hash is unchanged by construction.
- **Determinism and hash.** A scene without `GroundMist` is byte-identical (no read beyond one empty query; the extract is not part of the state hash anyway). A scene with it differs only in the saved component and in frames. The level depends only on authoring, the hour and `wetness`, so two runs agree and save/load in the middle of a dawn gives the same level; a test evaluates the function at fixed ticks of a `WorldClock` run in one go and in two halves.
- **Quality tiers.** Low tier already drops volumetrics; the exp² fallback keeps a visible, cheap mist there. `r.volumetric 0` style switches fall to the same path. The fallback is uniform in height by nature, which the guide states.
- **Luau (13c).** `weather.set_mist{strength=, peak_hour=, rise_hours=, burn_hours=, base_humidity=, wet_gain=, weather_damp=, density=, thickness=, base_height=, exp2_density=, color={r,g,b}, enabled=}` and getters (the authoring plus read-only `weather.mist_level()` from the same `mist_level` function on the current `time_of_day` and `Weather`); named errors, values clamped to the Range, nothing written on error, a missing `GroundMist` raises (the setter never adds one), typed in `definitions.cpp`, same rules as `set_gust` and `set_bolt`. `samples/12_weather` gets a `GroundMist` on the Weather entity (its entity count is unchanged), a clock start near dawn if the sample already has a `WorldClock` (13c reads the sample first and, if it has none, authors the level by setting `time_of_day` through the existing Luau clock calls), and logs `mist:` every 150 ticks; its golden and log expectations move in that step, nothing else.

## Gates
- A scene without `GroundMist` (or with `enabled` 0 or a zero level) has an unchanged state hash and unchanged frames; every existing sample hash and golden stays byte-identical until 13c changes `samples/12_weather`, and only that sample's expectations move.
- `Weather`, `WetSurfaces`, `DayCycle`, `WorldClock` and `Environment3D` are never written by mist code: the extract changes only its local `render::Fog` and `render::Volumetrics`; a test hashes the resource and the `Weather` column with and without `GroundMist`.
- The level is a pure function of authoring, `time_of_day` and `Weather`; no stored float, no wall clock, no `rand`.
- No shader, pass or new render field is added; the only render-side values are the existing `Fog` and `Volumetrics` members.
- `kit3d.h` and `weather.h` are not edited (checked with `scripts/ci/include_fanout.py`); `ground_mist.h` is included only by the extract, the install, the script binding and the tests, so no seam PR is expected.
- Luau: setters clamp, bad types raise named errors and write nothing.

## Risks
- **Main risk: the look.** The existing medium is a smooth exponential height fog, so mist reads as a haze gradient and not as banks with edges; 13b judges this with real frames at dawn and noon, and the milestone ships as "ground haze with shafts" if it is good enough. Patchiness is explicitly deferred to a shader follow-up.
- **Two fog paths.** Applying the level to volumetrics and to the exp² fog must be mutually exclusive after `apply_quality`; a double application would thicken the Low tier, hence the "one path per frame" test.
- **Volumetric cost.** Raising density does not change the froxel cost, but a scene that never enabled volumetric fog takes the cheap fallback by design; the guide says to set `volumetric_fog` for shafts.
- **Dependence on `time_of_day`.** Scenes with no `WorldClock` have `time_of_day` -1 and show no mist; the guide says to add a clock, and the Luau setter's help text repeats it.
- **Fog colour fights `DayCycle`.** `DayCycle` rewrites `fog_color` each tick from keys; mist mixes toward its own colour only in the extract's local copy, so it never fights the writer, but a very bright dawn key can wash the mist out; the sample picks a dawn key that shows it.
