# M-WINDGUST — Seeded wind gusts that modulate an effective wind (milestone record)

**Status:** planned 2026-10-22 (12a, 12b done, 12c to 12d not started). **Owner: routine 2 thread (the M-VISUAL line).** Follow-up of M-WEATHER, M-WINDSWAY, M-WINDDIR, M-CLOUDS and M-WEATHERAUDIO: wind is a smooth function of the weather kind (`Weather.wind`, 0.1 clear to 1.0 storm), so foliage, rain, clouds and the wind bed all breathe at one constant strength. No Linear issues (free issue limit); this record is the tracker.

**Goal.** An opt-in kit component `WindGust` and one system produce deterministic gusts (rise, hold, fall, then a calm gap) from the seed and integer state. They raise an *effective* wind read by foliage sway, rain slant, cloud drift, the snow lee bias and the `WeatherAudio` wind gain, without ever writing `Weather.wind`. A scene without `WindGust` hashes, simulates and renders exactly as today.

**Not in scope:** a new shader or render pass (every consumer already takes a scalar or a batch/emitter field), changing `Weather` (its bytes and `wind` stay as they are), changing `WindSway`, `WindDirection`, `CloudLayer`, `SnowCover`, `Precipitation3D` or `WeatherAudio` bytes, gust direction changes (the heading stays `WindDirection`'s), per-tree phase offsets or a travelling gust front (one global scalar), gust sounds as separate one-shots (only the existing wind bed gain moves), physics wind forces, new audio assets.

## Design

- **Opt-in component, no new fields on existing ones.** New component `WindGust` (`mce/kit/wind_gust.h`, one per scene, the first in ECS order drives, registered by `install_weather`). Adding a saved field to `Weather` or `WindSway` would change the hash of every weather scene, so the state lives on a component existing scenes do not have. Authoring (all `Save`, with a `Range`): `strength` 0.6 (Range 0..3, how much a full gust adds: effective = wind * (1 + strength * gust)), `min_gap_s` 2 and `max_gap_s` 8 (Range 0..120, calm time between gusts, swapped if inverted), `min_rise_s` 0.4 and `max_rise_s` 1.5 (Range 0.05..30), `min_fall_s` 1 and `max_fall_s` 3 (Range 0.05..60), `min_peak` 0.4 and `max_peak` 1 (Range 0..1, the per-gust height), `seed` (u32, 0 is a valid seed), `affects` (u32 bit mask, default all five: 1 sway, 2 rain, 4 clouds, 8 snow, 16 audio; bits above 31 are ignored) and `enabled` 1. Engine-written and saved: `gust_q` (the current level, numerator over 2^24), `segment` (u32 gust counter), `tick` (ticks into the segment), `gap_ticks`, `rise_ticks`, `fall_ticks` and `peak_q` (the segment's hashed shape, stored so a `dt` change or an authoring edit mid-gust cannot jump the curve), `seeded` (0 until the first segment is built) and an explicit `pad_` (zeroed every tick; `state_hash` hashes raw bytes). Padding audit entry added.
- **System `kit_wind_gust` (kit, 12a).** `FixedUpdate_Pre`, anchored after `kit_wind_direction` (hence after `kit_weather`), registered by `install_weather` next to it; 12a confirms the anchor by reading `install_weather`'s order. The shape is a pure function of `(seed, segment)`: gap, rise and fall lengths and the peak come from `hash_mix(seed, segment * 4 + {0,1,2,3})` (the existing `hash_mix` used by `kit_lightning`), mapped into the authored ranges in fixed point, converted to ticks with one `ceil(seconds / dt)` at segment start (a whole-tick-rate snap as in `kit_wind_direction`) and then stored. Each tick `tick` advances by 1; the level is an integer ease: calm during the gap, then `peak_q * smoothstep(tick_in_rise / rise_ticks)` as a u64 integer polynomial, then the mirror over the fall; at the end of the fall `segment += 1`, `tick = 0` and the next shape is built. No float accumulator crosses a frame (the only float per tick is the one `ceil` at a segment start, from authoring and `dt`), no wall clock, no `rand`. NaN or inverted authoring falls back to the defaults; `dt <= 0` or NaN does not advance. Clamps are documented in the header like `WindDirection`'s.
- **Effective wind helper (kit, 12a).** A pure inline `effective_wind(const Weather&, const WindGust*, u32 consumer_bit) -> f32` in `wind_gust.h`: with no `WindGust`, `enabled` 0, the consumer's bit clear or a zero level it returns `Weather.wind` *bit-identically* (an early return of the same f32, not `wind * 1.0`); otherwise `clamp(wind * (1 + strength * gust_q / 2^24), 0, 1)` computed in f64 and rounded once. It is for the extract, the audio and the precipitation systems only and never feeds state. A calm wind gusts proportionally less, which is why a clear day (0.1) stirs and a storm (1.0) already saturates at the clamp; this is a deliberate look, recorded for the sample.
- **Consumers, in order of cost** (decided while planning from `grep wind` in `src/engine/kit`):
  - *Foliage sway (extract, cheap, 12b).* `Kit3DExtract` reads `sway_wind = sway_weather->wind` once per extract (`kit3d_extract.cpp` ~1339) and passes it to `apply_wind_sway` for both batch paths (~1441 and ~1540). Replace that one scalar with `effective_wind(..., sway bit)`; `apply_wind_sway` and the scatter cache are untouched (batch fields only, `entry->version` unchanged), so a gust never re-scatters.
  - *Cloud drift (extract, cheap, 12b).* `clouds.speed = weather->wind * cloudc->speed_scale` (~930) takes the effective wind. The layer offset advances in the render side from `speed`; 12b checks that it integrates the speed over time (so a gust speeds the drift up and does not teleport it) by reading the cloud scroll in `scene3d`, and records the answer.
  - *Snow lee bias (extract, cheap but weak, 12b).* `snow.wind_bias` (~874) is authored 0..1, not a wind strength. The effective bias becomes `clamp(wind_bias * (1 + strength * gust_q / 2^24), 0, 1)` only with the snow bit set; only a scene with `WindGust`, `Weather` and `SnowCover` changes. If 12b finds the uniform upload costs or the look is invisible it is dropped from the milestone and recorded in the step status.
  - *Rain and snow slant (system, 12c).* `kit_precipitation` already takes `wind = wx->wind` (precipitation.cpp ~119) into `apply_emitter` (`slanted`, `lean`). The scalar becomes `effective_wind(..., rain bit)`. The emitter fields are written through `set(...)`, which writes only when bits change, so a gust changes the emitter every tick of a gust and nothing outside one. The system must run after `kit_wind_gust`; 12c checks the anchor in `install_precipitation` and, if `kit_precipitation` can run before the gust system, adds the order with the existing `after` argument or, failing that, a small seam PR (see risks).
  - *WeatherAudio wind gain (system, 12c).* `kit_weather_audio` computes `wind_target = target_q(weather->wind)` (weather_audio.cpp:61). The target takes `effective_wind(..., audio bit)`; the existing fade ramp (`wind_q` moves by a fixed integer step toward the target) then smooths the gust over `fade_seconds`. Its anchor is `kit_weather`; it must also run after `kit_wind_gust`, same ordering note.
  - *Not wired:* `Weather.wind` itself and the Luau `weather.wind()` getter keep returning the smooth value; a new `weather.effective_wind()` getter exposes the gusted one (12d).
- **Determinism and hash.** A scene without `WindGust` is byte-identical: the helper returns `Weather.wind` itself, the consumers run no new branch that writes. A scene with `WindGust` differs by design (new saved component; the sample's golden moves in 12d only). Save and load in the middle of a gust resume on the same hash because the segment shape, `tick` and `segment` are saved and the next tick reads nothing else. N ticks after a load equal N ticks without it; the level at tick T is also a pure function of `(authoring, seed, T from the start)`, which a test checks by running to T in one go and in two halves.
- **Safety.** No `Weather`, no `WindGust` or `enabled` 0: the system returns before writing, so the world is untouched. A `WindGust` without a consumer writes only its own state.
- **Luau (12d).** `weather.set_gust{strength=, min_gap=, max_gap=, min_rise=, max_rise=, min_fall=, max_fall=, min_peak=, max_peak=, seed=, affects=, enabled=}` and getters (the authoring plus read-only `weather.gust_level()` (`gust_q` over 2^24) and `weather.effective_wind()`); named errors, values clamped to the Range, nothing written on error, a missing `WindGust` raises (the setter never adds one), typed in `definitions.cpp`, same rules as `set_audio` and `set_bolt`. `samples/12_weather` gets a `WindGust` on the Weather entity (its entity count is unchanged) and logs `gust:` every 150 ticks; its golden and log expectations move in that step, nothing else.

## Gates
- A scene without `WindGust` (or without `Weather`) has an unchanged state hash and unchanged frames; every existing sample hash and golden stays byte-identical until 12d changes `samples/12_weather`, and only that sample's expectations move.
- `Weather.wind` (and the whole `Weather` column) is never written by gust code: a test hashes it with and without `WindGust`.
- All gust state is integers (`gust_q`, tick counters, `peak_q`); no float is carried from one tick to the next. The level at a tick depends only on authoring, seed and tick count. No wall clock, no `rand`.
- Save and load in the middle of a gust resume on the same state hash, and N ticks after the load equal N ticks without it. Two runs of `samples/12_weather` stay deterministic.
- Padding of `WindGust` is explicit and zeroed (padding audit).
- No shader, pass or new render field is added; every consumer change is a scalar substitution in the extract or a system.
- Include fan-out of the new header stays small (checked with `scripts/ci/include_fanout.py`; `wind_gust.h` is included only by the extract, the two systems, the install and the tests), and `weather.h`, `wind_sway.h` and `wind_direction.h` are not edited, so no seam PR is expected.
- Luau: setters clamp, bad types raise named errors and write nothing.

## Risks
- **System order.** `kit_precipitation` and `kit_weather_audio` must run after `kit_wind_gust`, but each is anchored to one earlier system and may be registered before the gust system. If an `after` list cannot express it, a small seam PR in the shared order code comes first; otherwise a gust would reach those consumers one tick late (still deterministic, only delayed), which 12c may accept and document.
- **Emitter churn.** A gust changes emitter direction and gravity on every tick of the gust; if the particle system treats a changed emitter as a restart or the change tracking is costly, 12c quantises the effective wind fed to rain to 1/64 steps.
- **Storm saturation.** At wind 1.0 the clamp hides gusts; the sample uses a Rain weather (0.5) so the effect is visible, and the guide says so.
- **Cloud scroll.** If the cloud offset is `speed * time` and not an integral, a gust would make the layer jump; 12b must find out and either integrate in the render side's existing per-frame update or drop clouds from the milestone.
