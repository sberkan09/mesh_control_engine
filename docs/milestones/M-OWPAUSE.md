# M-OWPAUSE: pause menu, options, save/load in 09_openworld (2026-10-31)

Esc (gamepad Start) now opens a pause menu in `samples/09_openworld`: RESUME, SAVE, LOAD, OPTIONS, QUIT TO DESKTOP. It holds the game while visible. OPTIONS opens a page with master volume (`audio.master_db`) and look speed (`input.look_sensitivity`) sliders and BACK.

Kit: `UiFlowDo` gets `SaveSlot` and `LoadSlot` (appended; values 6 and 7). The slot name is the rule's `field` (empty: `quick`). `SaveSlot` writes the slot with the current scene, tick and playtime; it only reads the world, so the state hash is unchanged. `LoadSlot` asks the host to apply the slot after the tick (`scene::request_load`), loading the rule's `scene` first when set. Both run on held ticks. A bad name or missing slot logs and does nothing. No new component; the design note is section J of [M-OPENWORLD-GAPS](M-OPENWORLD-GAPS.md).

Sample (generated by `gen_assets.py`): `ui/pause.mcui`, `ui/options.mcui`, entities "Pause menu" and "Options menu", `SaveKey 999` on the Player, a `Resume` action (Esc, Start) on the UI map.

Tests: `tests/kit/test_ui_flow.cpp` (save while held, load request, missing slot, bad name), `test_mcp_openworld` (counts; Pause holds the player, Resume walks).

Limits: one slot ("quick"); no "saved" message; health, ammo, seat state, traffic and police come back as authored after a load; no invert-look option.
