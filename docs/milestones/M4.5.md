## Gates

| Gate | Result |
|---|---|
| FR-EDT-160 acceptance: an MCP edit saves a `.mcscene` byte-identical to the same edit made through `EditorScene` commands, and `run_headless` gives the same hash | `test_mcp` "FR-EDT-160 gate": a pickup entity created with components, a duplicated crate moved by property path, a label text patched; both files are byte-identical; the MCP `run_headless`, the C++ `run_headless` and `mce_player -headless 1` all give the same 300-tick hash |
| Scripted transcript test (initialize → tools/list → calls → end of input, golden responses) | `mcp_transcript`: `tests/mcp/transcripts/demo_edit.jsonl` against its golden (state hash and log tail normalized, text content checked equal to `structuredContent`) |

| All inside `scripts/ci/local_ci.sh` | `test_mcp`, `mcp_transcript`, `mcp_symbol_wall` run in every preset's ctest; walls in the `walls` stage |

## Demo

From a fresh clone and a `linux-gcc-debug` build, an MCP client connected to `mce_mcp --project <copy of
samples/scene_demo>` adds a pickup (sprite + circle sensor collider), moves it by property path, saves, cooks, and
calls `run_headless` for 300 ticks, getting a hash back with progress notifications on the way. This is
`tests/mcp/transcripts/demo_edit.jsonl`, replayed against its golden in every CI preset.

## Slip notes

- **Demo project:** the plan named `samples/03_platformer`, but its level is built in C++ (`game/level.h`), not a
  `.mcscene`, so there is no scene for the tools to open. The demo uses `samples/scene_demo`, the editor project
  the catch-up built for this loop. Moving the platformer level into a scene file is game-content work for M6/M7.
- **Stretch items cut:** attach-to-running-editor and `render_frame`. Neither carries an FR; both reuse
  `mce_mcp_core` unchanged when picked up.
- **Not in the MVP:** cancelling a running tool (calls are synchronous; `notifications/cancelled` is ignored),
  recorded input for `run_headless`, and assert pass/fail in its result (the log tail carries warning/error counts
  instead).
- **Tracy:** the linked `mce_mcp` carries the engine-wide Tracy client and its on-demand listener (ADR-0027 §6). A
  strict no-network build is `-DMCE_ENABLE_TRACY=OFF`.
- **`.mcp.json`** points at the `linux-gcc-debug` tree and edits `samples/scene_demo` in place (its `cooked/`
  output is git-ignored). Other platforms and presets change the `command` path.
