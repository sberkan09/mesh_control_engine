# Mesh Control Engine — Roadmap

**Project:** Mesh Control Engine (MCE) · **Document class:** Roadmap / plan
**Date:** 2026-10-06 · **Last revised:** 2026-10-15 (engine gap tracks added: M-WEB, M-GAMEPLAY3D, M-CINEMA, M-NET2, M-TERRAIN, M-ACCESS) · **Status:** AUTHORITATIVE sequencing for the tiers defined in `REQUIREMENTS.md` §6. Dependency-ordered; **every milestone ends in a running, demonstrable build** (the invariant from REQUIREMENTS §7.4). Sizes are relative (S ≈ 2–4 wk, M ≈ 4–8 wk, L ≈ 8–14 wk, XL ≈ 14–22 wk at the 10–15 h/wk baseline; velocity re-checked per NFR-B-07 — **cut feature scope, never the gate, never the demo**). Every milestone also carries an **effort estimate in hours** (engineering + content production, published next to the size); the tier bands in §2's tier map are the *sums* of those estimates — if a milestone's actual hours exceed its estimate by > 50 %, the named overrun-absorber milestone cuts per the ladder (see the tier map note).

Milestone naming note: the FR tables in REQUIREMENTS carry indicative M0–M5 tags; this document is the sequencing authority and maps to *tiers* (MVP / v0.5 / v1.0), not to those tags.

Sequencing rationale (binding): 2D gameplay precedes 3D rendering polish because Artifact A is the earliest shippable artifact and the cut ladder's final rung reduces the MVE to Artifact A alone — Artifact B is structured as an **addition, not a dependency** (REQUIREMENTS cut-ladder rung 7). The cook pipeline precedes everything that loads content; the determinism harness precedes everything that could break it.

### M2 — Assets: cook it, map it, reload it · **size L (≈ 110–170 h engineering)** · tier: MVP

**Builds:** `.mce` container (header/TOC/CRC/version, fuzz + negative tests) · GUID registry + `.mceasset` sidecars · cook library + `mce_cook.exe` (scan, dep graph, topological cook, content-addressed outputs, CI exit codes) · importers: PNG → RGBA8, WAV → 48 kHz float32, TTF → font atlas, `.mcscene` → columnar scene chunk (reflection-driven) · `mce_refl` (field registry, `MCE_COMPONENT`) + inspector round-trip in the editor (moved here from M1) · **minimal entity spawn/select/delete in the editor (the authoring path the M2 demo needs — finding F54; full CRUD + gizmos in M3)** · mmap runtime load path · shader cook — **MVP slice: `glslangValidator -V` validation per stage at cook + the ≤ 1 s full program rebuild-and-swap (DX-H1, the load-bearing DX feature) + the binding-bank conformance checker (via glslangValidator's reflection dump, not a stored blob)**; *variant enumeration and the SPIR-V reflection blob are deferred to v0.5 by slip note (finding F9)* · scene save/load in the editor via `SceneDocument` + reflection serialization · job system learned cook-side (M2 per core R9).

**Demo (running):** author a scene in the editor (sprites + text), Save → Cook → load in `game.exe`; cook twice ⇒ byte-identical (CI); edit a fragment shader → pixels change ≤ 1 s without restart; a broken asset yields a file+line cook error in the editor panel while the old asset keeps rendering. `03_platformer` begins as static content.

### M-VISUAL — High-end 3D rendering · **size XL (rough guess, ≈ 250–400 h engineering, not estimated per step)** · tier: off-tier renderer track, gates nothing

*Added 2026-10-13 by the user's request, after an assessment of the 3D path against current high-end rendering. Today's `Forward3D` (GGX PBR, Forward+ point/spot lights, sun CSM, HDR, bloom, ACES, MSAA/FXAA, LOD, skinning) suits stylized and low-poly 3D (Ashen Court, SolsticeReach), but has no compute path, no global illumination, no pre-filtered IBL, no screen-space effects, no point/spot shadows and no temporal pipeline. This track closes that gap step by step; each step is opt-in per scene or quality tier, keeps the GL backend as the reference (Metal and SDL GPU follow per the M-MAC parity rule) and degrades on the Low/Medium tiers so mobile budgets hold. Ray tracing and a Vulkan/D3D12 desktop backend stay in M10+ (N14).*

**Builds, in order:** (1) compute in the RHI: compute pipelines, `dispatch` / `dispatch_indirect`, storage images (read/write textures) and the barriers they need, on GL first, then SDL GPU and Metal; the clustered light build moves to the GPU · (2) image-based lighting (picks up the IBL cut from M8): environment cubemap from the sky or an equirect, GGX pre-filtered mip chain, BRDF LUT, SH9 irradiance (split-sum ambient replaces the two-color hemisphere), plus placed reflection probes with box projection, baked in the editor and cooked · (3) SSAO/GTAO at half resolution with a bilateral blur, applied to ambient only · (4) local-light shadows: a shadow atlas for spot lights and cube shadows for point lights, budgeted per frame by screen importance, with the same PCF filtering as the sun · (5) temporal pipeline: a velocity buffer (skinned and moving meshes included), jittered projection, TAA with neighborhood clamping replacing FXAA on the High tier, then temporal upscaling so `render_scale` < 1 stays sharp · (6) global illumination: an irradiance-probe volume (DDGI-style, compute-updated, static geometry first) with a baked fallback for Low; lightmaps only if probes miss the quality bar · (7) atmosphere and volumetrics: physically based sky/atmosphere scattering driven by the sun angle (time of day), froxel volumetric fog lit by the sun and local lights, light shafts · (8) post completion: auto exposure (histogram), color-grading LUT on the 3D path, depth of field, per-object motion blur, SSR (optional, after TAA) · (9) scale: GPU-driven frustum and occlusion culling with indirect draws, instanced foliage, a decal system, GPU particles for 3D.
**Demo:** a new sample (or SolsticeReach with a "high" profile) shown side by side with the current frame at the same camera positions and times of day: interiors lit by bounced light, local lights casting shadows, reflections that match the environment, volumetric fog at dusk; the Low/Medium tiers still hit their mobile budgets on the same scene.
**Gates:** per-step golden captures and a per-stage GPU budget table extended from M5a's (High tier at 1080p: ≤ 16.6 ms total on a mid-range desktop GPU, each step's cost recorded); every step can be turned off and the frame with everything off matches today's output; GL validation clean; `local_ci.sh` green on every step.

**Builds, in order:**
1. Scripts as assets: `.luau` sources compiled and type-checked by `mce_cook` into a `CHNK_SCRIPT` bytecode chunk; the player and `run_headless` load bytecode only, so the Luau compiler links into the cook and the editor, never the player (a wall). A scene names its scripts and their phases (a `ScriptSystem` list in the scene settings), and the stock player, the editor's play mode and `mce_mcp` run them.
2. A complete API: cached field handles (`mce.field("Comp", "field")`) in place of per-call name lookups, `spawn` / `destroy` / `add` / `remove` and prefab instancing through `Commands`, events read and written by reflection, `InputState`, resources, 2D and 3D physics queries and `move_and_collide`; budget: the spike's 2,000-entity bench at ≤ 0.4 ms per tick in Release.
3. No hidden state: a compile-time check over Luau's AST rejects assignments to outer locals and `pairs` over non-string keys (ADR-0041 open questions 2 and 3), so a script's memory is its components; saves, replays and a reload between two ticks keep the hash.
4. Tooling: Luau type definitions generated from the reflection registry (`mce.d.luau`), MCP `script_check` (diagnostics as `file:line:col`) and script errors in `run_headless` and `test_run`, the editor console with jump-to-line, hot reload during play-in-editor, Tracy zones per script, and script stacks in crash reports.
5. The compiler-free path: `mce new --script` makes a project with no C++ module, `mce ship` packages it with the stock player, and the same pack plays on Android, iOS and the web player (`MCE_WITH_SCRIPT` on in the mobile and web presets).
6. Docs and the demo: a user guide chapter, kit recipes in Luau, `docs_search` coverage, and the `start_game` prompt offering a script project.

**Demo:** Ember Step's player controller and an enemy FSM ported to Luau pass the same `.mctest` scenarios as the C++ versions; a fresh agent in a blind test makes a script-only 2D game over MCP with no compiler installed, and its pack plays in the browser.
**Gates:**
- The determinism stage covers script games (3 runs, Debug = Release) and the Luau-vs-C++ twin.
- Sandbox, step-budget and memory-cap tests stay green; the walls keep Luau's headers in `mce_script` and the compiler out of the player.
- A project without scripts builds and hashes exactly as today.
- `local_ci.sh` green on every step.

4. **RenderDoc capture per new render feature** merged before the feature is (FR-DBG-020).
5. **Learning gate closed**: the milestone's LRN doc written from memory + self-exam recorded; a gate that cannot close in its timebox cuts feature scope, never the gate (FR-DX-080).
