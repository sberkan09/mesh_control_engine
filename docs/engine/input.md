# input — tick-quantized device sampling and action maps

`mce_input` is an L2 library in `src/engine/input/`. Its public dependencies are `mce_core`,
`mce_platform`, `mce_ecs` and `mce_refl` (`src/engine/input/CMakeLists.txt`). It turns timestamped
`platform::Event`s into one immutable `InputState` per simulation tick. Gameplay reads
`InputState` and never sees a device or an SDL event. It is linked by `mce_ui`, the `mce_engine`
umbrella, the project editor executables generated by `cmake/MceProject.cmake`, and the samples
`03_platformer` and `05_ashen_court`.

The layering is one-directional: platform events (L1 device state) are folded per tick window,
action maps (L2) evaluate bindings into actions, and the snapshot (L3) is what the sim reads.

## Public surface

Headers live under `include/mce/input/`.

- `actions.h`: the only header gameplay includes.
  - `InputState`: the per-tick snapshot. Fast-path fields filled from same-named actions (`move`,
    `look`, `trigger_l/r`, `jump_*`, `fire_pressed`, `pause_pressed`, `confirm_pressed`,
    `cancel_pressed`), named access (`action`, `pressed`, `released`, `held`, `axis`, `axis2`,
    `has_action`), `text()` (UTF-8 typed during the tick), `mouse_pos_px()`, `mouse_wheel()`.
  - `ActionState` (value, `held_time`, `held`, `pressed`, `released`), `ActionType`
    (`Button`, `Axis1D`, `Axis2D`), `kMaxActions` (64), `kMaxTextBytes` (64).
  - `operator==` and `hash_state()` (FNV-1a over the sim-visible content) for replay and
    determinism tests. `app::ActionSnapshot` in `mce/app.h` is an alias of `InputState`.
- `input_map.h`: the action-map data. `Device` (keyboard, mouse button / wheel / delta, gamepad
  button / axis), `Curve`, `Deadzone`, `BindingDef`, `ActionDef`, `ActionMapDef`
  (`MapFlag::BlocksBelow`), `InputMapHeader` (chunk magic `MCIM`, version 1), `InputMapSet`,
  `decode_input_map` / `encode_input_map`, and `InputMapBuilder` for code-side authoring.
- `input_system.h`: `InputSystem`, the engine-internal API that hosts and the run loop call. It
  implements core's `app::IInputSource`.
  - Maps: `load_map(chunk)`, `push_map` / `pop_map` (overlay stack, up to 8), `rebind`.
  - Capture rebinding: `begin_rebind(map, action, index, timeout_s, accept)`, `cancel_rebind`,
    `rebind_state`, `rebind_result`.
  - Persistence: `binding_overrides`, `reset_bindings`, `serialize_bindings` /
    `deserialize_bindings`, `save_bindings(path)` / `load_bindings(path)`.
  - Clock: `set_tick_rate`, `set_tick_origin_us`, `tick_close_us`.
  - Per frame and tick: `begin_frame(events)`, `push_event`, `sample_for_tick(tick)`, `state()`.
  - Raw device state for editor cameras and tools (not gameplay): `key_held`, `mouse_held`,
    `mouse_pos`, `gamepad_connected`, `gamepad_held`, `gamepad_axis`.
  - `set_recorder`, `set_replayer`, `stats()` (`InputStats`: folded, dropped, ignored events).
- `bindings.h`: `BindingOverride` (a reflected struct, `MCE_REFL_STRUCT`), `write_bindings` and
  `read_bindings` for the text save format. `Device` and `Curve` are reflected with `MCE_ENUM`.
- `default_map.h`: `build_default_map` and `default_map_chunk`, the starter-kit maps "Gameplay"
  (Move, Look, Jump, Fire, Pause) and "UI" (`BlocksBelow`: Navigate, Confirm, Cancel), keyboard,
  mouse and gamepad.
- `ecs.h`: `install(world)` registers a zeroed `InputState` resource; `publish(world, state)`
  copies the tick's snapshot into it.
- `replay.h`: `InputRecorder` (appends the live part of each snapshot) and `InputReplayer`
  (`next` returns false at the end or on corrupt data).

## Rules and invariants

- **Tick quantization (FR-INP-030).** Tick N owns the half-open window
  `[origin + (N-1)·T, origin + N·T)`, with boundaries computed as integers
  (`origin + N·1'000'000 / tick_hz`). `sample_for_tick` folds, in timestamp order, every queued
  event stamped before the tick's close; later events wait. A tick's input is therefore
  independent of render rate. Ticks must be sampled in increasing order (asserted). Under
  `app::run` the loop passes each tick's close through `IInputSource`.
- **Edges.** Pressed and released edges are derived per tick from folded state. A tap shorter than
  a tick still shows held for one tick. OS key repeat is not a new press.
- **Focus loss.** `FocusOut` resets device state: everything reads released and the release edges
  fire once.
- **Editor capture.** Events flagged `EventFlag::ConsumedByEditor` are ignored for presses, but
  releases still land, so no key sticks.
- **Unknown actions.** An unknown name reads as a zero state and logs one error per distinct name
  in a row (FR-DX-050), never a crash.
- **Map stack.** The top map's actions shadow same-named actions below; a `BlocksBelow` map hides
  everything beneath. `load_map` resets the stack, held state and edges.
- **Gamepads read "any pad".** A button is held while any pad holds it; an axis takes the largest
  deflection. Pads go through the same quantization as keyboard and mouse.
- **Rebinding.** A captured press is swallowed and applies from the next sampled tick. Escape
  always cancels. The timeout counts sim time, so replays behave the same.
- **Persistence.** Overrides re-apply on every `load_map`. `save_bindings` writes a temp file and
  renames it. Overrides naming a map, action or index the current map lacks are dropped with one
  warning; `load_bindings` returns `FileNotFound` when no save exists.
- **Allocation.** The event queue holds `kQueueCapacity` (1024) events; on overflow the oldest is
  dropped and counted, and the queue does not grow. `InputState` is a flat value type.
- **Cooked layout.** `BindingDef` (20 B), `ActionDef` (16 B), `ActionMapDef` (16 B) and
  `InputMapHeader` (20 B) are frozen by `static_assert`. Adding an action to a map changes the
  sim-visible `InputState`, and with it a game's determinism hash (ADR-0026 §2.3).
- **Threading.** Main thread only.
- **Walls.** No SDL here (SDL wall and SDL include wall in `scripts/ci/check_walls.py`); the
  engine container ban applies.

## How it is tested

`test_input` (`tests/input/`, no GPU, links `mce_input`; files written to a build-tree `tmp`
directory). Helpers are in `input_test_util.h`.

- `test_actions.cpp`: chunk round-trip and corrupt data, composite WASD, per-tick edges,
  "taps shorter than a tick still show for one tick (1-tick visibility floor)", key repeat,
  "focus loss zeroes held state and fires release edges once", editor capture, overlay maps,
  unknown action names, deadzones and curves, in-session rebinding, mouse delta and text, world
  resource publishing, "app::run samples InputSystem once per tick through IInputSource".
- `test_quantization.cpp`: "FR-INP-030: identical sim-visible input at 30/90/240 Hz render
  rates", exact rational tick boundaries, events at a tick's close wait, queue overflow.
- `test_gamepad_rebind.cpp`: stick and d-pad on Move, "any pad", pad quantization at different
  render rates, capture rebinding, stick capture onto an axis, "FR-INP-040: bindings round-trip
  through reflection and survive a restart", bad and stale binding files.
- `test_replay.cpp`: "60 s of recorded input replays identically through sample_for_tick",
  corrupt streams rejected.
- The virtual-pad hot-plug path is tested in `test_platform`.

## Known gaps

- ADR-0026 §2 "Not built": per-player pad ownership (bindings read any pad until local
  multiplayer) and the rebinding UI screen. Rumble exists only as `platform::gamepad_rumble`, with
  no input-map surface.
- The default maps have no trigger actions on purpose: a new action changes the `InputState`
  layout and the 03_platformer determinism hash (ADR-0026 §2.3).
- M7: no relative-mouse or pointer-lock mode in `mce_platform`, so mouse look uses raw deltas.
