# script — Luau scripts as ECS systems (`mce_script`, `mce_script_compiler`)

Scripts are the way to write game logic without C++. A `ScriptHost` owns one sandboxed Luau VM; each
script is loaded from bytecode and its `update()` runs once per tick as a system. Everything a script
does goes through the global `mce` table. ADR-0041 has the decision; the
[user guide chapter 27](../user-guide/27-scripting.md) teaches it; this page is the reference for what is
built and where its limits are.

## Surface

| Header | What it gives |
|---|---|
| `mce/script/script.h` | `ScriptHost`, `ScriptBudget` (step budget, memory cap, `check_state`), the list of `mce` functions in its header comment |
| `mce/script/scene_scripts.h` | `install_scene_scripts`: runs the scripts a scene names with `kit::ScriptSystem` components (`order`, `phase`, `during_cutscenes`) |
| `mce/script/compiler.h` | `compile`, `add_source`, `compile_unchecked`: source to bytecode, with the type and name checks. The shipped player never links it |

Registered `mce` functions live in `src/engine/script/src/script.cpp` (fields, `each`) and `api_world.cpp`
(everything else: entities, events, input, 2D and 3D physics, navigation, saves, rotations, noise).

## `mce.d.luau`: the typed reference

`mce.d.luau` is the `mce` API as Luau type definitions, generated by `src/engine/script/compiler/definitions.cpp`:
the function signatures are fixed in that file, and the component, event and field lists come from the
reflection registry, so it always matches the build that wrote it.

- The cook writes it to `cooked/mce.d.luau` and type-checks every script against it.
- `mce mcp` / `script_check` with `definitions: true` returns the text for an agent.
- Editors (luau-lsp) read the cooked file for completion.
- `test_script_api` compares the registered functions with the names it declares, both ways, so a function
  cannot be added without its declaration.

This is the complete, current function list with argument and result types; the guide's table (27.3) is the
same list with explanations.

## Limits

What a script cannot do, and what to do instead:

| Limit | Why | Instead |
|---|---|---|
| No state between ticks: no counters in top-level locals, tables or closures | the state hash, saves and replays must cover everything a script remembers | keep it in a reflected component (`ScriptVars` for a script's own numbers). The cook rejects the visible cases; at run time frozen tables and compared upvalues and buffers catch the rest (`script.state_check`) |
| `for k, v in t` over a table keyed by tables or functions is not caught | iteration order follows addresses, and Luau runs that loop inside the VM | key by entity, number or string |
| One component per field pair, or one handle per field | `mce.get` / `mce.set` name each field (`mce.get(e, "A", "x", "B", "y")` spans components) | resolve handles with `mce.field` at the top level |
| `Perceiver.sees` and `.heard` are numbers (`0` / `1`), not booleans | they are `u8` fields; booleans come only from `bool` fields | compare with `== 1` |
| No quaternion type | rotations are Euler degrees as a `vector` (x pitch, y yaw, z roll; forward -Z) | `mce.rotation3d`, `mce.set_rotation3d`, `mce.look_rotation3d`. Straight up or down reads back as yaw 0 with the turn in roll |
| No `os`, `io`, `debug`, `coroutine`, `print`, `math.random` | determinism and the sandbox | `mce.log`, `mce.random`, `mce.tick` |
| A script cannot load code or assets that carry code | bytecode is trusted only from the game's own pack (`MountOptions::allow_code`) | data-only packs for mods |
| Budget per tick and a memory cap | a runaway script must not stall the loop | a script that errors or runs over is disabled and logged; the others keep running |

## Tests and gates

- `tests/script`: sandbox, budgets, field access, the API (`test_script_api`), the state guard (`test_script_state`),
  scene scripts and the player end to end (`player_scripts` exits 3 for a failed script).
- Script-only projects (`"games": []`; Dungeon, Pursuit) add `<Name>_mctests`, `<Name>_perf_counters` and a seeded
  perf variant through `mce_add_script_project`; the determinism stage plays their autopilot input.

## Known gaps

- The static state check is a heuristic: it follows top-level locals, `local a = t.x` aliases made inside a function and writes into global
  tables, not helper parameters or `newproxy` metatables (those fail at run time).
- A shipped game's window leaves the run-time state check off by default (`-script.state_check 1` turns it on).
